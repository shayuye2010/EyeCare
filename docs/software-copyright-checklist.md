# 软件著作权申报整理清单

## 一、建议申报信息

| 字段 | 建议填写 | 待确认内容 |
| --- | --- | --- |
| 软件全称 | EyeCare 亮睛睛护眼提醒软件 | 是否使用“V1.0”后缀，以申报表要求为准 |
| 软件简称 | EyeCare | 可不填或填写 EyeCare |
| 版本号 | V1.0 | 与最终提交代码保持一致 |
| 软件分类 | 应用软件/工具软件 | 以登记系统分类选项为准 |

| 首次发表状态 | 未发表或已发表 | 公开 Git 仓库、发布包可能涉及发表认定 |

## 二、通常需要准备的材料

- 计算机软件著作权登记申请表。
- 个人身份证明，或企业营业执照及法定代表人/经办人材料。
- 软件源程序鉴别材料。
- 软件说明书或操作文档，建议使用 [software-description.md](software-description.md) 继续排版成 PDF。
- 非独立开发时的合作开发协议、委托开发协议、权利转让协议或其他权属证明。
- 软件名称、版本、著作权人和开发完成日期的内部确认记录。

具体格式、页数、签章和提交方式应以中国版权保护中心当前申报页面的要求为准。

## 三、源代码整理建议

1. 固定一个申报归档版本，例如 `V1.0`，保存对应的 Git 提交号、构建包和说明书。
2. 整理前端和 Rust 源代码，优先包含核心业务逻辑、界面交互、计时、状态、数据存储和桌面桥接代码。
3. 排除 `node_modules`、构建产物、缓存、压缩包、截图和第三方库源码。
4. 保留文件名、相对路径和必要的版权注释，使鉴别材料能够对应源代码结构。
5. 检查源代码首尾提交片段是否连续、页码是否符合申报系统要求，避免只提交界面静态文本。
6. 对外部依赖、图标、字体、音效和复制改写的代码建立授权记录。

本项目建议重点整理：

- `src/app.ts`：主界面、交互流程、提醒和统计；
- `src/timer.ts`：计时引擎；
- `src/state.ts`：状态模型、数据迁移和校验；
- `src/storage.ts`：本地持久化；
- `src/interaction.ts`：桌面交互保护逻辑；
- `src-tauri/src/lib.rs`：托盘、窗口、遮挡层和 Windows 原生能力。

## 四、提交前自查

- [ ] 申请人名称在申请表、说明书、权属证明中完全一致。
- [ ] 软件名称和版本号在申请表、说明书、源代码归档和发布包中一致。
- [ ] 开发完成日期有 Git 记录、构建记录或其他材料可以佐证。
- [ ] 已确认所有第三方代码和素材的许可范围。
- [ ] 已确认 GPL-3.0-only 开源方式与申请人权利主张一致。
- [ ] 说明书已转换为 PDF，并检查截图、页码和中文字体显示。
- [ ] 源代码已去除密钥、个人隐私、构建缓存和无关文件。
- [ ] 已保存提交版本的源代码压缩包、可运行程序和校验值。
- [ ] 已根据官方最新要求完成签字、盖章和在线提交。

## 五、建议留存的证据

- Git 仓库提交记录和标签。
- 构建日志、测试结果和发布包。
- 软件运行截图和版本信息截图。
- 第三方依赖清单及其许可证。
- 图标、字体、音效和图片的创作或授权来源。
- 个人开发过程记录，或公司内部立项、开发和验收记录。
